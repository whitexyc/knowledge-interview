# Agent 能力成长路线图（工程化关）

> 定位：从「单 Agent 流水线」走向「多 Agent 分布式系统」的能力补全路线。
> 依据：项目复盘结论 —— 观测是"记录式"不是"链路式"、成本是"记账"不是"预算"、失败是"单点重试"不是"隔离恢复"，且缺"任务"抽象这根底座。
> 状态：路线规划，模块启动后逐项在 specs/module-XXX/ 闭环。

## 现状基线（已具备）

| 能力 | 状态 |
|------|------|
| 检索/记忆/评估 | ✅ 强（三路召回 + 重排 + 图谱 + 三层记忆 + 评估集） |
| 工具自主调用 | ✅ 10 个内置工具（手写 ReAct） |
| 跨系统调用 | ✅ RAG↔Java 反向闭环（module-080） |
| 防注入守卫 | ✅ 出题侧 `<kb_reference>` + 入库审查节点（module-074/075-078） |

## 缺口 → 模块映射

### 阶段 A：工具治理与外部接入（前置：不会调工具谈不上治理）
| 模块 | 内容 | 验收方向 |
|------|------|----------|
| module-083 | 工具治理：AgentTool schema 校验 / 幂等（同参不重放）/ 工具级超时 / 高风险工具人工审批 | 10 工具全部过 schema；高风险工具未经审批不可调用 |
| module-084 | 外部 MCP 客户端接入：作为 MCP client 发现 + 注册外部工具进 registry，复用既有工具白名单 | 接 1 个真实外部 MCP server，工具可被 Agent 调用且受治理约束 |

### 阶段 B：可观测（记录式 → 链路式）
| 模块 | 内容 | 验收方向 |
|------|------|----------|
| module-085 | 可视化看板：成功率 / 延迟 P95 / 成本 / 工具调用次数（基于 request_logs/tool_call_logs） | 看板页面输出 4 指标，数据与落库一致 |
| module-088 | 链路式观测：trace_id 跨进程传播 + span 树（因果父节点）+ 决策级日志（为什么选这个工具/分支） | 一次请求对应一条 trace，父 span 含决策原因 |

### 阶段 C：安全（防得住）
| 模块 | 内容 | 验收方向 |
|------|------|----------|
| module-086 | 注入防护实测：知识库投毒用例集 → 输入/输出过滤 → 量化拦截率 | 用例集 ≥20 条，拦截率可量化上报 |

### 阶段 D：任务化底座（隐藏底座，前三件事的挂载点）
| 模块 | 内容 | 验收方向 |
|------|------|----------|
| module-087 | 任务抽象：task 表（task_id/intent/status/预算/父子链）+ 一次请求 = 1 task = N Agent = M 调用 | 观测聚合/预算/checkpoint 均挂在 task 上 |
| module-089 | 预算账本：任务级 token/成本预算 + 超预算熔断 | 超预算任务被熔断，成本可控 |
| module-090 | 失败隔离 + checkpoint：子 Agent 失败不连坐 + 长任务断点恢复 | 模拟子失败 → 父任务不失败；重启后续跑不从头 |

### 阶段 E：复杂编排实验
| 模块 | 内容 | 验收方向 |
|------|------|----------|
| module-091 | LangGraph 复刻实验 → 转正对比报告（框架 vs 自研，同一评测集） | 对比报告含耗时/成本/成功率，结论可复现 |

## 关键设计约束

- **状态所有权**：多 Agent 并发写记忆会脏写 → "子只读父写"模型（在 module-087 任务抽象中一并落地）
- **Agent 级最小权限**：工具白名单从全局细化到 Agent 粒度（在 module-083/084 中落地）
- 每一关是下一关前置：A（治理）→ B（观测）→ C（安全）→ D（任务化）→ E（编排），D 是 B/C 的挂载底座，可并行推进 A/B/C
