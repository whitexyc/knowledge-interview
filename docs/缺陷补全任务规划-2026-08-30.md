## 二、任务清单（每条带验收，可直接开工）

### T1（P0）上下文 Token 预算分配 + 工具结果压缩【上下文工程核心】
- **做什么**：chat/agent 主路径加 ContextBudget：system/工具结果/历史/检索内容分段硬预算；工具返回超限按策略压缩（检索结果→取 top 压缩、结构化数据→截断+统计摘要）；历史→滑窗。
- **为什么**：Agent 爆 Token 头号元凶是工具返回不是聊天；这是你"上下文工程"叙事里缺的最后一块，补上后四支柱齐了。
- **涉及**：`agent/react.py`、`agent/langgraph_react.py`、chat 主路径。
- **验收**：① 预算配置化（各段可调）② 超限压缩路径有单测 ③ 消融实验：预算开/关的 token 消耗与答案质量对比（落 METRICS）④ module 三件套。

### T2（P0）工具执行前 schema 硬校验闸
- **做什么**：execute_tool_with_log 执行前用 args_schema 做 jsonschema 校验（jsonschema 库）；幻觉工具名/参数不合法 → 结构化错误返回给模型（让模型自纠），不抛裸异常。
- **为什么**：业界六大事故模式之一"幻觉工具名"的标准防御；ToolRegistry 已有 schema，只差执行闸，改动小收益大。
- **涉及**：`agent/react.py` execute_tool_with_log、`agent/tool_registry.py`。
- **验收**：① 幻觉工具名/坏参数单测拦截 ② 结构化错误信息模型可读 ③ 存量测试全绿。

### T3（P1）ReAct 熔断升级：计数 → 计数+成本+再锚定
- **做什么**：现有 phase budget（计数）之上加：① token 成本累计熔断 ② 每 N 步"目标再锚定"（把原始目标重新注入，对照当前动作是否漂移）。
- **为什么**：状态漂移（state drift）是长任务头号事故模式；Google Antigravity 无限重试删生产服务就是没有成本熔断。
- **涉及**：`agent/langgraph_react.py`（加 cost accumulator + re-anchor 节点）。
- **验收**：① 成本超限触发兜底（非硬崩）② 再锚定节点单测 ③ 长任务模拟测试（10+ 步）漂移收敛。

### T4（P1）入库纵深防御：爬虫侧 sanitize + canary + 信任分级
- **做什么**：module-076 爬虫 → module-078 审查节点之间插入清洗层：① 剥离零宽字符/隐藏文本/常见注入模式 ② 每篇外部内容嵌 canary token（若检索后出现在 LLM 输出中可检测）③ 来源信任分级（官方文档/白名单社区/未知，低信任降权或人工审）。
- **为什么**：Java 出口守卫只防"检索结果操纵出题模型"，入口不防"恶意内容进库"。纵深防御 = 入口+出口两层。这也让你的防注入故事从"一层"变"纵深"，面试含金量翻倍。
- **涉及**：爬虫 pipeline、审查节点（078 之上）、新 ADR。
- **验收**：① 注入样例数据集（构造 20+ 恶意样例）拦截率有实测数 ② canary 全链路单测 ③ 白名单/黑名单分级生效。

### T5（P1）Supervisor 编排：闭环"学习 Agent"第二模式
- **做什么**：反向闭环（080 低分题→待学笔记→优先级抓取）目前是线性脚本；升级为 Supervisor 模式——supervisor 动态分派：分析薄弱点 → 派"检索Agent"查知识库 → 派"出题Agent"生成补弱练习 → 汇总学习计划。
- **为什么**：你只有"图内接力"一种编排；补 Supervisor 后有两种一手对比经验（何时选哪种），这是面试高频题。
- **涉及**：rag-service agent 层新增 supervisor 图；Java 侧展示学习计划。
- **验收**：① 与接力模式的对比记录（适用场景/成本/延迟）② 端到端演示：一次低分面试 → 生成学习计划 ③ 深挖文档落档。

### T6（P2）SAG 增益验证（诚实闭环）
- **做什么**：module-081/082 已实施但未见公开基准对比数；跑 ecom-zh/nfcorpus 对比 hybrid vs hybrid_sag（Hit@5/延迟），写出"何时 SAG 有增益/何时不值得"结论。
- **为什么**：没有数据的 SAG 是面试风险点（"你 SAG 提升多少？"答不出）；有数据（哪怕负增益）就是加分项——"我测过，单跳语料增益 X%，多跳场景才值得"。
- **验收**：基准数字落 METRICS + 结论写进深挖/SAG 文档。

### T7（P2，整理项）specs 单一事实源
- **现状**：ADR/模块 specs 仍在 interview-personal/specs/，代码已在 knowledge-interview。建议把 specs/adr + module 三件套迁入 knowledge-interview（或明确 README 指向），避免"代码在 A、档案在 B"。
- **验收**：knowledge-interview README 链接到 specs；git mv 保留历史。

## 三、顺序与节奏

```
T2(小,1-2天) → T3(小) → T1(中,含消融) → T4(中,含恶意样例集) → T5(大) → T6(跑基准)
```
- 先小后大：T2/T3 快速拿两个"安全带"落地；
- T1 是上下文工程核心，配消融实验出数字；
- T4 依赖爬虫真实抓取（已有），防御才有靶子；
- T6 随时可插队（GPU 空闲时跑）。
- 全程不需要新项目、不需要新基础设施——全是给已有系统补"安全带和仪表盘"。
